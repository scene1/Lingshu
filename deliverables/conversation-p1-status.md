# 灵枢对话模块 P1 实施状态

更新时间：2026-08-21

## 已实现

- 结构化长期记忆：事实、偏好、决定、待办、推断五类；当前只自动启用用户明确表达的内容。
- 记忆去重、相关性检索、近期加权、跨会话注入、归档和删除。
- 敏感信息过滤：API Key、Token、密码、私钥等内容不进入长期记忆。
- OpenKB 查询缓存、来源归一化、命中指标、延迟、错误、过期缓存降级和状态接口。
- 工具治理：按会话和工具限流，按只读、网络、写入、高风险分组审批。
- 高风险工具不支持永久放行，只能每次确认或始终拒绝。
- 审批请求、审批结果、策略阻断和限流进入统一工具审计日志。
- 60 条质量基线报告持久化，并按模型生成通过率和评分趋势。
- GitHub Actions 每日执行协议测试与构建；自托管 macOS Runner 可选执行真实模型样本。
- App 新增“对话质量”页面，管理长期记忆、评测趋势、OpenKB 指标和工具治理。

## 默认策略

- 只读：直接允许。
- 网络：每次确认。
- 写入：每次确认。
- 高风险：每次确认。
- 每个会话、每个工具独立限流；高风险默认每分钟 3 次，OpenKB 默认每分钟 6 次。

## 仍需外部条件

- 完整 60 条真实模型评分会产生调用费用，仍需显式运行 `npm run eval:conversation`。
- OpenKB 指标只有在 Sidecar 启用后才会产生真实命中数据。
- 夜间真实 Provider 回归需要自托管 macOS Runner、已运行的灵枢后端和 GitHub Variables。
