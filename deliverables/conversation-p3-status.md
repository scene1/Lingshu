# 灵枢对话模块 P3 实施状态

更新时间：2026-08-21

## 已实现

- Prompt/Policy Registry：每次修改生成独立版本，不允许原地修改生效策略。
- 默认 v1 策略完整映射 P2 Conversation Runtime v2 的 Prompt、温度、输出预算、工具轮数、工具超时、上下文预算、记忆 TopK、工具数量和知识检索开关。
- 候选策略只能处于草稿；绑定通过质量 Gate 的固定评测报告后才能进入 `validated`。
- 固定评测支持 `LINGSHU_EVAL_POLICY_ID`，以非持久模式真实运行指定候选策略，避免拿 Active 策略成绩给候选版本盖章。
- 评测报告保存后可自动绑定对应策略；评测请求不进入生产灰度遥测。
- 灰度按 `sessionId + policyId` 哈希稳定分流，同一会话始终命中同一版本。
- 同一时间只允许一个 Canary；启动新灰度时旧 Canary 自动回滚。
- 灰度记录请求数、成功、错误率、平均延迟和用户有用反馈。
- 达到最小样本后，错误率或相对延迟超过阈值会自动回滚，并写入统一审计日志。
- Canary 达到最小健康样本后才能激活；激活时保留上一 Active 版本作为回滚点。
- 支持 Active/Canary 手动一键回滚，恢复上一 Active 版本。
- AI 对话步骤、回复协议、会话消息 Runtime 元数据和 Run History 均记录实际策略 ID、版本和 active/canary/evaluation 变体。
- 用户点赞、点踩、采纳和拒绝会归属到生成该回复的策略版本。
- App“对话质量”新增“策略版本”页签，支持创建、编辑、绑定评测、启动灰度、激活、回滚和删除可删除状态版本。

## 安全边界

- 含有绕过审批、绕过权限、忽略安全规则或泄露密钥要求的 Prompt 候选在创建阶段直接拒绝。
- 未通过 Gate 的策略无法启动灰度，界面和 API 均无绕过入口。
- 灰度上限为 50%，正式激活必须满足最小样本与错误率门槛。
- 只有草稿、已拒绝和已回滚策略可删除；Active、Canary 和已验证版本不可直接删除。
- 策略系统不能修改密钥、工具权限或默认分支，也不能自动发布桌面包。

## 默认灰度门槛

- 灰度比例：10%。
- 最小样本：20 次。
- 最大错误率：10%。
- 最大平均延迟回归：相对 Active 1.5 倍。

## 仍需外部条件

- 候选策略的完整 60 条真实模型评测会产生 Provider 调用费用，需要配置 `LINGSHU_EVAL_MODEL` 和 `LINGSHU_EVAL_POLICY_ID` 后运行。
- 当前自动回滚使用错误率和延迟；语义质量回滚仍依赖用户反馈积累或后续独立评审模型。
- 目前只对 Conversation Runtime v2 生效；显式选择旧 Runtime v1 或 Claude CLI 兼容路径仍使用原有固定参数。
