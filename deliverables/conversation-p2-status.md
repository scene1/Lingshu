# 灵枢对话模块 P2 实施状态

更新时间：2026-08-21

## 已实现

- Memory v2：保留 P1 数据兼容，新增作用域、来源 Episode、冲突关系、替代关系、纠正时间和过期时间。
- 同一记忆槽位出现不同值时，普通表达进入待确认，不会静默覆盖；明确“改为/更新为”才自动建立替代链。
- App 支持采用新值、保留旧值和创建纠正版；旧记录保留为 `superseded`，便于追溯。
- 到期记忆自动转为 `expired`，不再进入模型上下文。
- 正式质量门槛：最小样本数、总体通过率、平均评分、平均延迟、关键类别通过率共同决定是否可发布。
- 默认完整门槛为 60 条、总通过率 90%、平均评分 75%、平均延迟不高于 60 秒；事实边界和安全审批类别必须 100% 通过。
- 多 Provider 对比：按每个模型最新报告展示样本、通过率、评分、延迟、Gate 状态和相对差值。
- 夜间回归支持 Provider A/B 连续运行同一套 60 条基线，并按服务端 Gate 结论返回 CI 成败。
- OpenKB 配置持久化：启用状态、Sidecar 地址、知识库名称和令牌；令牌不通过 API 回传。
- OpenKB Sidecar 地址限制为本机回环地址，降低 SSRF 和误连内网服务风险。
- App 支持保存 OpenKB 配置并执行连接、版本和知识库存在性诊断。

## 默认安全策略

- 冲突记忆默认待确认，旧值继续生效。
- 被拒绝、过期、归档和被替代记忆不会注入模型上下文。
- 单条冒烟报告即使 100% 通过，也会因为样本和关键类别不足而被 Gate 拒绝。
- OpenKB 仍是可选 Sidecar；未启用或不可用时不阻断普通对话。
- OpenKB 配置文件以仅当前用户可读写权限保存，界面只显示令牌已配置状态。

## 仍需外部条件

- 完整真实模型 A/B 评测会产生 Provider 调用费用，需要配置模型后显式运行或启用夜间任务。
- OpenKB 真实连接需要本机已经运行兼容的 Sidecar 服务；P2 不自动下载或执行第三方 Python 项目。
- 当前评测评分器以确定性协议检查为主；引入独立评审模型前，语义质量仍需人工抽检。

## 下一步建议

- P3 建立 Prompt/Policy Registry，把 Prompt、路由和检索策略版本绑定到评测报告、灰度状态和一键回滚。
- 增加用户反馈原因、纠正内容和实际采用行为，作为长期学习证据。
- 为 OpenKB 增加文档编译队列、失败重试和来源级命中质量统计。
